- schedule.create model: pass the model ID exactly as the provider lists it. Some providers embed the provider prefix inside the modelID itself (i.e. the full reference is `provider/<provider>/model`); truncating to a single prefix stores an invalid modelID and the spawned session dies instantly (failed, 0 tokens) — and the scheduled run can still report success. Verify by reading the spawned session's messages, not the scheduler's status.
- schedule.create only accepts a registered project: arbitrary worktree or repo directories fail with "Project not found". Pass the registered projectId and put absolute repo paths inside the prompt text.
